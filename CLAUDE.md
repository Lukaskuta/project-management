## Project

"Helper" — a project/ticket management app (Kanban, Scrum, road map, timesheets, Jira import) built on Laravel 9, Filament 2 (admin panel is the whole UI), Livewire 2, Tailwind/Vite. Requires PHP 8+, MySQL 8+ and a Pusher account. User docs live in `docs/` (docsify site, published at https://devaslanphp.github.io/project-management).

## Commands

- Full setup: `composer install-project` (npm install, composer install, build assets, copy `.env.example`, key:generate, migrate, db:seed). Configure DB/mail/Pusher in `.env` first or the migrate step fails.
- Serve: `php artisan serve`; assets: `npm run dev` (Vite) or `npm run build`.
- Queue worker (needed for notifications/emails and Jira import): `php artisan queue:work`
- Reset DB: `php artisan migrate:fresh --seed` — seeds the default user `john.doe@helper.app` / `Passw@rd` with all permissions.
- After config/settings changes: `php artisan optimize:clear`
- Tests: `php artisan test` (or `vendor/bin/phpunit`); single test: `php artisan test --filter=test_name`. Only Laravel's example tests exist, and `phpunit.xml` does not switch to SQLite, so tests hit the `.env` database.
- Lint/format: `vendor/bin/pint` (Laravel Pint).
- Docker: `docker-compose.yml` runs the published `eloufirhatim/helper` image with MySQL; the image's `run.sh` starts the queue worker, migrates, seeds, builds assets and serves on port 8000. CI only builds/pushes that image on `master`.

## Architecture

- **UI is Filament.** CRUD screens are `app/Filament/Resources/*Resource.php` (with `Pages/` and `RelationManagers/`); custom screens are `app/Filament/Pages/` (Kanban, Scrum, Board, RoadMap, JiraImport, timesheet pages, `ManageGeneralSettings`); dashboard widgets in `app/Filament/Widgets/`. Navigation groups (Management, Referential, Security, Settings) are registered in `AppServiceProvider`. Livewire components embedded in these pages are in `app/Http/Livewire/`. `routes/web.php` only holds a few extras (ticket share link, account validation, road-map JSON data, OIDC).
- **Permissions:** spatie/laravel-permission with string permission names like `List tickets`, `View ticket`, `Create ticket`, plus extras (`Manage general settings`, `Import from Jira`, …). They are created by `database/seeders/PermissionsSeeder.php` — a new module or permission must be added there, and checked in a policy in `app/Policies/` (policies also restrict viewing to project owner/members/ticket owner/responsible).
- **Runtime settings:** `App\Settings\GeneralSettings` (spatie/laravel-settings; migrations in `database/settings/`, not `database/migrations/`). `AppServiceProvider::configureApp()` reads them at boot and overrides app name, locale, logo, registration, social/OIDC login config. Static behavior config (locales list, project member roles, ticket relation types, max file size) is in `config/system.php`.
- **Projects:** `type` is `kanban` or `scrum` (Kanban and Scrum pages redirect to each other based on it; shared logic in the `App\Helpers\KanbanScrumHelper` trait). `status_type` is `default` (global `TicketStatus` records) or `custom` (per-project statuses managed via `StatusesRelationManager`) — ticket status selects must branch on it.
- **Ticket side effects live in `Ticket::boot()`:** code generation (`<project ticket_prefix>-<n>`), ordering, status-change `TicketActivity` records, watcher notifications, and syncing `epic_id` from the sprint. Status changes need an authenticated user (`auth()->user()->id`).
- Referential models (ticket types/priorities/statuses, project statuses, activities) use soft deletes; relations to them use `withTrashed()`.
- Attachments and covers use spatie/laravel-medialibrary; Excel exports in `app/Exports/` (maatwebsite/excel); Jira import runs as `App\Jobs\ImportJiraTicketsJob` using `App\Helpers\JiraHelper`.

## Translations

All UI strings go through `__('...')`. Per-locale JSON files are in `lang/*.json` (60+ locales), generated by Google Translate via custom commands: `php artisan make:lang <locales>` (generate and translate a locale file) and `php artisan trans:missing <base>` (fill missing keys from a base locale). Add new strings in English and regenerate rather than hand-editing every locale.
